# 6.0.0：组件化桌面界面与任务容错

## 构建与发布

- 所有分支推送与 PR 都测试 Windows、Linux、macOS Apple Silicon / Intel；Vue 只构建一次，各安装包复用相同资源。
- 保留自动打包范围：dev 仅 Windows；beta 为 Windows + macOS；main、版本标签、手动运行构建全部平台。PR 只验证，不发布安装包。
- macOS 统一为 `VideoMergingTool-macos-universal.dmg`，应用、Python 运行时与 FFmpeg / FFprobe 均须包含 arm64 和 x86_64。不能将两个 PyInstaller 应用简单拼接。
- 构建使用固定 Python Universal 2 安装包与同一版本的两套 FFmpeg 原生工具，下载后校验 SHA-256。Python 安装输入位于 `scripts/macos-build-inputs.json`，FFmpeg 输入位于 `videomerge/env_check.py`。
- 同一 DMG 分别在 `macos-15` 和 `macos-15-intel` 挂载，验证签名、架构、动态库依赖、Vue 资源与内置工具的实际合并结果，均通过才允许标签发布。Universal 2 指 CPU 架构兼容，不代表已验证所有旧版 macOS。
- 本地 macOS 默认也构建 Universal 2，需要已安装的 python.org 双架构 Python；通过 `VMT_PYTHON_BINARY` 指定。只构建本机版本时可以设置 `MACOS_TARGET_ARCH=arm64` 或 `x86_64`。CI 安装脚本不会在本地修改系统 Python。

## 用户行为

- 默认：快速抽检，检测到异常时停止任务。用户可以改为跳过确认损坏的视频并继续。
- 基础检查只读取容器和媒体参数。快速抽检解码开头、中间、结尾各约 3 秒；不超过 9 秒的视频检查全段。完整检查解码全段，不生成中间视频。
- 抽检不保证未覆盖位置完整。定位可能受容器索引影响；检查超时、缺少可靠时长或无法明确归因时停止，不自动当成损坏文件跳过。
- 读取失败的文件会在列表上方显示原因，可显式从本次任务排除。
- 单文件转码失败时，GPU 路径可回退 CPU 重试。只有进一步完整检查确认输入异常，且策略为跳过时，才排除该输入。
- 磁盘空间、输出权限、编码器配置等任务级故障停止任务。不能定位到坏源文件的拼接错误也会停止。
- 剩余文件保留全局排序中的相对位置。视觉分组不参与生成合并顺序；旋转、排除不移动行。
- 视频表格使用 AG Grid Community，自行渲染方向分隔行，不使用 Enterprise 行分组。文件名使用剩余空间，其他列按全部已加载数据计算内容下限；操作列固定右侧。手动列宽会保存，可重置。
- 日志界面使用虚拟列表，可筛选警告和错误并导出完整日志。
- 结果分为全部完成、部分完成、失败、已取消。跳过清单包含源文件、阶段和原因，可重新载入失败文件。
- 成片先写入同目录的临时文件，校验通过后发布。失败不会覆盖已有成片。

## 架构

```text
frontend/src/
  App.vue                    桌面工作区
  useWorkspace.ts            API、选择、排序、任务轮询与设置
  ordering.ts                全局顺序与视觉分组
  components/VideoTable.vue  AG Grid 视频表格
  components/SettingsPanel.vue
  components/TaskResult.vue
  components/LogPanel.vue
videomerge/
  gui.py                     本地服务、原生选择窗口、进程控制
  reliability.py             有界检查、失败策略、任务报告
  cli.py                     检查与合并调度
  transcode.py               单文件隔离与 GPU 回退
  merge.py                   拼接恢复、校验后发布
  web/                       自动构建的离线前端资源，不提交到 Git
```

Python 服务和 FFmpeg 继续本地运行。前端依赖只参与开发和构建，安装应用的用户不需要 Node.js。静态资源来自安装包，不使用 CDN。

桌面任务的 `process.log` 和 `result.json` 保存到应用配置目录下的 `runs/<任务标识>/`。取消时清理本次临时处理目录；开启保留临时文件时保留诊断产物。

## 源码开发

需要 Python 依赖、Node.js 22.12+（构建流程使用 Node.js 24）和 npm。

```bash
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run build
python -m unittest discover -s tests
python main.py gui
```

修改前端后重新构建，再刷新桌面窗口。`scripts/build_local.sh`、`scripts/build_windows.ps1` 会构建并打包前端；CI 已接入 Node.js、前端测试和 Python 测试。

## CLI 新增参数

```bash
python main.py merge /path/to/videos --mode extreme --check-level quick --on-error skip --report-file result.json --log-file process.log
```

`--check-level basic|quick|full`，默认 `quick`；`--on-error stop|skip`，默认 `stop`。有输出但排除了部分输入时，报告状态为 `partial`，进程退出码为 0；无输出或任务级故障退出码为 1。试运行不执行解码检查，也不生成视频。

## 回归重点

- 正常输入、损坏文件头、元数据可读取但数据段被截断的真实 FFmpeg 样本。
- 停止与跳过策略、跳过后的顺序和最终时长、未知结果不被误当成可跳过。
- 输出失败不覆盖旧文件、拼接失败定位后重试、系统故障不误跳过输入。
- 旋转不移动视觉分组、排除恢复原位、方向分组不影响实际合并排序。
- Windows、macOS、Linux 的原生选择窗口和桌面安装包需要在对应系统上做发布验收。
